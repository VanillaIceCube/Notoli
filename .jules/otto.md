# Otto's Backlog Organization Journal

## 2026-09-07 - Direct GitHub REST API Backlog Audit **Learning:** When command-line tools like `gh` are absent in the execution environment, querying the GitHub REST API (`https://api.github.com/repos/VanillaIceCube/Notoli/issues` and `/pulls`) directly via Python or curl allows comprehensive inspection of all open issues, PRs, labels, assignees, and branch state. **Action:** Future backlog audit runs without `gh` CLI should query GitHub REST API endpoints directly to maintain full visibility across the open backlog.

## 2026-09-07 - Protecting Active Specialist Implementation **Learning:** Active PRs from specialist agents (such as Marty's test optimizations and board drawer error handling, Nora's notepad custom hook refactoring, and Forge's notification CRUD resilience) represent in-flight work against active tickets. Restructuring issue scope or closing tickets while implementation PRs are under review creates goalpost movement and disrupts implementation cycles. **Action:** Never split, merge, close, or re-scope active issues while specialist implementation PRs are actively open and under review.

## 2026-09-07 - Automated Security Alert Issues **Learning:** Security alert issues (prefixed with `<!-- notoli-security-alert:...`) are automatically synchronized and managed by scheduled workflows (`alert-codeql.yml`, `alert-vulnerability.yml`, `alert-malware.yml`). Manual modifications to their titles or bodies can disrupt automated tracking. **Action:** Leave security alert issues to automated workflow reconciliation and focus manual backlog organization on product, engineering, and architecture tickets.

## 2026-09-08 - Upstream FullStackTemplate Adoption Issues **Learning:** Issues prefixed with "Adopt FullStackTemplate ..." (e.g. #668-#676) represent explicit cross-repository parity adoption objectives. Although they do not have active implementation PRs open at this moment, they form a structured epic roadmap designed to be implemented by specialist agents. **Action:** Preserve the scope and boundaries of upstream adoption tickets; do not consolidate or fragment them unless explicit upstream changes occur.
